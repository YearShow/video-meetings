# video-meetings

**Встречи, файлы и расшифровки в одном месте — а данные остаются у вас.**

video-meetings — self-hosted приложение для команд, которые записывают созвоны и хотят быстро возвращаться к тому, что на них обсуждалось. Создайте встречу, добавьте участников, загрузите запись — и через несколько минут получите текст разговора. Приложение разворачивается на вашем сервере, а расшифровка записей выполняется локально.

## Что умеет

- **Встречи с участниками.** Создаёте встречу и приглашаете коллег по email: они видят её и её файлы в своём аккаунте.
- **Файлы встреч.** Загрузка записей и материалов до 500 МБ с прогрессом и возможностью отмены, список файлов, скачивание по короткоживущей ссылке.
- **Автоматическая расшифровка.** mp3 и mp4 расшифровываются локально через whisper.cpp (русский язык): виден статус, прогресс, готовый текст, а при ошибке можно запустить заново.
- **Контроль над данными.** Записи, файлы и расшифровка (whisper.cpp) остаются на вашем сервере. Исключение — будущая AI-выжимка: для неё текст транскрипта отправляется во внешний сервис Claude (через Claude Agent SDK); запускается вручную, кнопкой, отдельно для каждой встречи.
- **Запуск одной командой.** PostgreSQL и api поднимаются через Docker Compose.

**Скоро:** AI-выжимка встречи — краткое резюме, список задач с ответственными и принятые решения ([PRD](docs/prd-meeting-ai-summary.md), в разработке). Обработка идёт через Claude Agent SDK, то есть текст транскрипта уходит во внешний сервис Anthropic.

## Кому и когда полезно

- **Небольшим командам и фрилансерам**, у которых созвоны с клиентами и коллегами записываются, но искать нужный момент в часовой записи некогда: проще открыть текст и найти фразу.
- **Когда записи не хотелось бы отдавать сторонним сервисам расшифровки**: NDA, персональные данные, внутренние обсуждения — аудио и видео расшифровываются локально и никуда не отправляются. Если вы пользуетесь AI-выжимкой, учитывайте, что её текст обрабатывает внешний сервис Claude.
- **Когда нужен свой инструмент**: развернули на своём сервере, файлы и транскрипты лежат в вашем PostgreSQL и volume.
- **Когда нужно быстро вспомнить договорённости**: после созвона весь материал встречи — записи, файлы, текст — собран в одном месте.

Стек: Next.js 16 (`apps/web`), Nest.js 12 + Prisma + PostgreSQL (`apps/api`), npm workspaces.

## Быстрый старт

Нужны Node.js >= 24, npm 11 и Docker.

```bash
npm install
cp .env.example .env                      # значения по умолчанию подходят для разработки
cp .env.example apps/api/.env             # DATABASE_URL, JWT_SECRET, FILES_DIR и др.
docker compose up -d postgres
npm run db:deploy -w apps/api             # миграции
npm run dev                               # web :3000, api :4000
```

## Переменные окружения

Пример всех переменных — `.env.example`.

| Переменная                   | Где     | Назначение                                                                             |
| ---------------------------- | ------- | -------------------------------------------------------------------------------------- |
| `POSTGRES_*`                 | compose | параметры PostgreSQL                                                                   |
| `DATABASE_URL`, `JWT_SECRET` | api     | подключение к БД и секрет JWT (обязательны)                                            |
| `FILES_DIR`                  | api     | каталог файлов встреч (обязательна; локально `./storage`, в Docker — `/data/files`)    |
| `MAX_UPLOAD_BYTES`           | api     | лимит размера файла, по умолчанию 524288000 (500 МиБ), не больше 2³¹−1                 |
| `WHISPER_BIN`                | api     | бинарник whisper.cpp для транскрибации, по умолчанию `whisper-cli`                     |
| `WHISPER_MODEL_PATH`         | api     | путь к модели `ggml-base.bin`; без него транскрибация завершается ошибкой              |
| `FFMPEG_BIN`                 | api     | ffmpeg для извлечения звука из mp4, по умолчанию `ffmpeg` из PATH                      |
| `TRANSCRIPTION_CONCURRENCY`  | api     | сколько файлов расшифровывается одновременно, по умолчанию 1                           |
| `TRANSCRIPTION_RECOVERY`     | api     | `off` отключает возврат незавершённых задач в очередь при старте                       |
| `WEB_ORIGIN`                 | api     | origin `web` для CORS, по умолчанию `http://localhost:3000`                            |
| `PORT`, `API_PORT`           | api     | порт api (4000) и порт на хосте в compose                                              |
| `API_URL`                    | web     | адрес api, по умолчанию `http://localhost:4000`                                        |
| `MAX_UPLOAD_BYTES`           | web     | лимит файла в интерфейсе, должен совпадать со значением у api (по умолчанию 524288000) |

## Файлы встреч и Docker

`docker compose up -d --build api` запускает api в контейнере (миграции применяются при старте, `JWT_SECRET` обязателен). Файлы лежат в именованном volume `api_files` (`/data/files`) и переживают пересоздание контейнера; удалить их можно только вместе с volume (`docker compose down -v`). Не запускайте контейнер одновременно с `npm run dev:api`: порт 4000 общий.

## Транскрибация (Whisper)

mp3 и mp4, загруженные во встречу, автоматически расшифровываются локальным whisper.cpp (модель `base`, язык русский); сама расшифровка не использует внешние сервисы. Модель в репозитории не хранится.

**В Docker.** Образ `api` уже содержит `whisper-cli` (собирается из исходников, первая сборка занимает несколько минут) и `ffmpeg`. Нужно только положить модель в `./models` (или в каталог из `WHISPER_MODELS_DIR`) и запустить:

```bash
mkdir -p models
curl -L -o models/ggml-base.bin https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-base.bin
docker compose up -d --build api
```

Без модели файл получит статус «Ошибка: Файл модели Whisper не найден», после добавления модели его можно перезапустить кнопкой «Повторить».

**Локально (macOS).** `brew install whisper-cpp ffmpeg`, модель скачайте так же, в `apps/api/.env` задайте абсолютный `WHISPER_MODEL_PATH`.

## Как мы работаем (воркфлоу с Claude Code)

Проект разрабатывается в паре с Claude Code. Каждая фича проходит один и тот же путь от идеи до PR:

1. **Требования.** `/prd <фича>` — Claude вместе с нами формулирует цель, сценарии и скоуп и сохраняет `docs/prd-<фича>.md`.
2. **План.** `/plan-phase <фича>` — PRD разбивается на независимые фазы: первая — «tracer bullet» (тонкий сквозной срез), у каждой фазы есть задачи и критерий готовности. Результат — `docs/plan-<фича>.md`.
3. **Бэклог.** `/issues` — по плану через `gh` создаются milestone на каждую фазу и issues на задачи.
4. **Реализация.** Идём фаза за фазой: обычно сначала backend с тестами, затем web. Перед завершением прогоняем `npm run lint`, `typecheck`, `test` и `format:check`; хук `pre-commit` (Husky) запускает lint и тесты, и мы не обходим его через `--no-verify`.
5. **Коммит и PR.** `/git-commit` собирает коммит по Conventional Commits, дальше — pull request.
6. **Ревью.** Перед слиянием — скилл `requesting-code-review` и агент `security-reviewer` (проверка на уязвимости).

Пример такой цепочки: [`docs/prd-meeting-file-transcription.md`](docs/prd-meeting-file-transcription.md) → [`docs/plan-meeting-file-transcription.md`](docs/plan-meeting-file-transcription.md) → реализация по фазам.

### Скиллы

Скиллы — это готовые инструкции для Claude под конкретный тип задач.

- Свои, лежат в `.claude/skills/`: `prd`, `plan-phase`, `issues` — шаги воркфлоу выше.
- Установленные, лежат в `.agents/skills/`: `git-commit`, `requesting-code-review`, `nestjs-best-practices`, `vercel-react-best-practices`, `heroui-react`, `ui-ux-pro-max`. Источники и хэши — в `skills-lock.json`; вручную их не правим, обновляем через установщик скиллов. В Claude Code они подключены симлинками из `.claude/skills/`.

### Файлы CLAUDE.md

`CLAUDE.md` — постоянный контекст проекта, который Claude читает автоматически в начале работы: структура, команды, соглашения, архитектура. Они есть в корне, в `apps/web` и в `apps/api`: общие правила — в корневом, локальные — в приложении. Правило проекта: меняем архитектуру — обновляем документацию в том же изменении.

Подробности для разработки — в `CLAUDE.md` (корень и `apps/*`).

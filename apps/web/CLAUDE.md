# apps/web

Фронтенд на Next.js 16 (App Router), React 19, TypeScript, Tailwind 4. Исходники в `src/`, алиас импортов `@/*` → `src/*`.

@AGENTS.md

## Команды

Из корня репозитория: `npm run <script> -w apps/web`. Из этой папки — просто `npm run <script>`.

- `dev` — dev-сервер (`next dev`).
- `build` / `start` — production-сборка и запуск.
- `lint` / `lint:fix` — ESLint (`eslint.config.mjs`, на базе `eslint-config-next`).
- `test` / `test:watch` — Vitest + Testing Library (jsdom, `vitest.config.mts`, `vitest.setup.ts`); тесты лежат рядом с кодом как `*.test.ts(x)`. Server Actions и `apiFetch` в тестах мокаются через `vi.mock`.
- `typecheck` — `next typegen && tsc --noEmit`. `next typegen` нужен, чтобы появились глобальные типы вроде `LayoutProps`.

## Соглашения

- Роуты и layout лежат в `src/app/`. По умолчанию используйте серверные компоненты, `"use client"` только там, где он необходим.
- Стили через Tailwind, глобальные стили в `src/app/globals.css`. UI-компоненты — HeroUI v3 (`@heroui/react`, стили `@heroui/styles` подключены в `globals.css`): без Provider, составные компоненты (`Card.Header`), обработчики `onPress`.
- Обычные запросы к API идут с сервера Next (Server Actions), а не из браузера. CORS в `api` включён только для загрузки файлов из браузера (origin `WEB_ORIGIN`, JWT в заголовке `Authorization`). Адрес API — `API_URL` (по умолчанию `http://localhost:4000`, см. `src/lib/api.ts`). JWT хранится в httpOnly-cookie `accessToken`.
- Страницы: `/` — главная (только для авторизованных: приветствие с email, число встреч, три последние по дате, кнопка «Создать встречу» с модальным окном, выход), `/meetings/[id]` — встреча с разделом «Файлы» (список: имя, размер, дата, автор; пустое состояние; сообщения об ошибках доступа и загрузки), `/auth/login` — вход, `/register` — регистрация. Формы и Server Actions лежат рядом со страницами (`src/app/auth/login/`, `src/app/register/`, `src/app/actions.ts`); ошибки сервера отдаются по полям через `fieldErrors` и `Form validationErrors`. Общие компоненты — `src/components/` (поле пароля с кнопкой «показать», окно создания встречи).
- Скачивание файла: Server Action `getDownloadLink` (`src/app/meetings/[id]/actions.ts`) просит у api короткоживущую ссылку (`POST .../download-link`, JWT остаётся на сервере), `DownloadButton` открывает её навигацией; имя файла задаёт `Content-Disposition` api. Ошибки списка файлов — `FilesResult` из `src/lib/files.ts` (403/404 → `forbidden`, сеть/5xx → `unavailable`, 401 → редирект `apiFetch`).
- Сессия: `src/lib/session.ts` (httpOnly-cookie `accessToken` на 1 час, как и JWT), запросы от имени пользователя — `apiFetch` в `src/lib/meetings.ts`. `src/proxy.ts` без cookie перенаправляет `/` и `/meetings/*` на `/auth/login` (оптимистичная проверка); если api отвечает 401, `apiFetch` ведёт на `/auth/expired`, который сбрасывает cookie и открывает логин с сообщением об истёкшей сессии.
- Включён `cacheComponents`: динамические данные (`cookies()`, `searchParams`, `fetch` к api) читайте внутри `<Suspense>`, иначе в консоли появится ошибка предрендера.
- Тёмная тема: HeroUI включает её классом `.dark`, его ставит инлайн-скрипт в `layout.tsx` по `prefers-color-scheme`. Не переопределяйте `--background` и `--foreground` в `globals.css`: это переменные HeroUI.
- Если `proxy.ts` создан или изменён при запущенном dev-сервере и не срабатывает, перезапустите `next dev`.
- Форматирование делает корневой Prettier; не добавляйте локальный конфиг.
- Файлы `next-env.d.ts` и `.next/` генерируются, вручную не правьте.

## Проверка UI

При любом изменении UI (страницы, компоненты, стили, тексты интерфейса) задача не считается завершённой, пока не выполнено всё из списка:

- Изменение проверено визуально в браузере через Playwright MCP (инструменты `mcp__playwright__*`, на запущенном dev-сервере): открыт реальный экран, пройдены основные сценарии, включая состояния ошибки и загрузки, посмотрены скриншоты и консоль браузера.
- Изменение проверено со скиллом `ui-ux-pro-max` (доступность, интерактивность и размеры целей нажатия, формы и обратная связь, адаптивность, типографика и цвет), найденные замечания исправлены.
- Проверка прошла и на узкой (мобильной) ширине, и в тёмной теме.
- Артефакты проверки (например, `.playwright-mcp/`) удалены из репозитория.

В итоговом сообщении укажите, что именно проверено визуально и какие замечания дал скилл.

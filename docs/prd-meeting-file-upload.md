# PRD: Meeting file upload

**Дата**: 2026-10-13
**Статус**: Draft

## Цель

Дать участникам встречи возможность загрузить к ней файл (запись, документ, презентацию) и видеть список загруженных файлов внутри встречи. Файлы сохраняются на сервере, чтобы их можно было обрабатывать позже (транскрипция и т. п. — отдельная фича).

## Пользовательские сценарии

- Участник открывает страницу встречи -> видит раздел «Файлы» со списком загруженных файлов (имя, размер, дата загрузки, кто загрузил) или пустое состояние.
- Участник выбирает файл через кнопку или перетаскиванием -> файл начинает загружаться, виден индикатор прогресса.
- Участник загружает файл до 500 МБ -> файл появляется в списке встречи со статусом «Загружен».
- Участник загружает файл больше 500 МБ -> загрузка не начинается, показано сообщение о превышении лимита.
- Участник отменяет загрузку в процессе -> файл не появляется в списке, на сервере не остаётся частично загруженных данных.
- Загрузка прервалась (сеть, ошибка сервера) -> показано сообщение об ошибке, можно повторить загрузку; файл в списке не появляется.
- Участник нажимает на файл в списке -> скачивает его.
- Пользователь, не являющийся участником встречи, пытается открыть список файлов или скачать файл -> получает отказ в доступе.

## В скоупе

- Загрузка файлов любого типа в рамках существующей встречи, один файл за раз, до 500 МБ.
- Хранение файла и его метаданных: оригинальное имя, MIME-тип, размер, автор загрузки, дата загрузки, встреча, статус (`Загружен`).
- API: загрузка файла, получение списка файлов встречи, скачивание файла.
- Интерфейс на странице встречи: кнопка выбора файла и drag-and-drop зона, прогресс загрузки, отмена, сообщения об ошибках, список файлов, скачивание, пустое состояние.
- Загружать и видеть файлы могут владелец и участники встречи (сопоставление по id пользователя).
- Приведение `participants` к id пользователей: валидация при создании встречи и миграция данных.
- Проверка доступа на каждом запросе (авторизация + принадлежность к встрече).
- Удаление файлов встречи при удалении самой встречи.
- Автотесты api (unit и e2e) на загрузку, лимит размера и проверку доступа; обновление документации (`CLAUDE.md`, `README.md`).

## Не в скоупе

- Обработка содержимого файла: транскрипция, конвертация, генерация превью, антивирусная проверка. Статусы обработки не вводим.
- Встроенный просмотр и воспроизведение (видеоплеер, просмотр PDF) — только скачивание.
- Одновременная загрузка нескольких файлов, очередь загрузок, возобновляемая загрузка (resumable/chunked).
- Удаление и переименование отдельных файлов.
- Облачное хранилище (S3 и т. п.) — в этой итерации только локальный диск.
- Квоты на пользователя или встречу, общий лимит хранилища.
- Публичные ссылки на файлы и шаринг за пределами встречи.
- Запись видеозвонка в самом приложении.

## Технические ограничения

- Максимальный размер файла — 500 МБ; лимит проверяется на сервере, а не только в интерфейсе.
- Типы файлов не ограничиваем, поэтому файл нельзя отдавать как исполняемый контент в браузере: скачивание принудительное (как вложение).
- Участник встречи сопоставляется с пользователем по `id`. Сейчас `Meeting.participants` — `String[]` без связи с `User`, поэтому значения в нём должны быть id пользователей (существующие данные и создание встречи нужно привести к этому правилу). Доступ к файлам имеют владелец (`ownerId`) и пользователи, чей id входит в участники встречи.
- Файлы хранятся на локальном диске сервера `api`; путь к каталогу задаётся переменной окружения (пример в `.env.example`). Каталог должен переживать перезапуск (в docker — volume) и не отдаваться как статика. Метаданные хранятся в PostgreSQL через Prisma. Хранилище должно быть за абстракцией, чтобы позже заменить его на S3-совместимое без изменения API.
- Архитектура `api` — CQRS (команды и запросы), новый функционал вписывается в существующий модуль встреч.
- `web` обращается к `api` на другом порту (3000 → 4000): учесть CORS и передачу JWT при загрузке.
- Имя файла от пользователя не используется как путь на диске (защита от path traversal).

## Критерии готовности

- [ ] Авторизованный участник встречи (id входит в `participants`) загружает файл ≤ 500 МБ, и он появляется в списке файлов встречи с именем, размером, датой и автором.
- [ ] Файл > 500 МБ отклоняется сервером с понятной ошибкой (HTTP 413), в списке не появляется; интерфейс показывает сообщение до начала отправки.
- [ ] Загрузка файлов типов разных категорий (видео, аудио, PDF, текст) проходит успешно.
- [ ] Во время загрузки отображается прогресс; отмена останавливает загрузку, файл не создаётся ни в хранилище, ни в БД.
- [ ] При ошибке загрузки показано сообщение и доступна повторная попытка; после ошибки нет «битых» записей в списке.
- [ ] Скачанный файл побайтово совпадает с загруженным (проверено на файле > 100 МБ), имя при скачивании совпадает с оригинальным.
- [ ] Файлы сохраняются после перезапуска `api`.
- [ ] Неавторизованный запрос получает 401, пользователь, чей id не входит в участники и не является владельцем, — 403/404 на список, загрузку и скачивание.
- [ ] Список файлов встречи отображается на странице встречи в `web`, включая пустое состояние; интерфейс работает на ширине от 375 px и доступен с клавиатуры.
- [ ] При удалении встречи её файлы удаляются из хранилища и БД.
- [ ] Для api написаны тесты: успешная загрузка, превышение лимита, отказ в доступе, скачивание; `npm run lint`, `npm run typecheck`, `npm run test`, `npm run format:check` проходят.
- [ ] Документация (`CLAUDE.md`, `apps/api/CLAUDE.md`, `apps/web/CLAUDE.md`, `.env.example`, `README.md`) обновлена: хранилище, лимит, новые эндпоинты и переменные окружения.

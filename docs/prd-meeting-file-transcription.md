# PRD: Транскрибация файлов встречи через локальный Whisper

**Дата**: 2026-10-15
**Статус**: Draft

## Цель

После загрузки аудио- или видеофайла во встречу система автоматически расшифровывает речь в текст локальной моделью Whisper (`base`) и показывает пользователю статус и прогресс расшифровки, а по готовности — текст. Это позволяет читать содержимое записи, не прослушивая её, без отправки данных во внешние сервисы.

## Пользовательские сценарии

- Пользователь загружает mp3 или mp4 во встречу -> файл появляется в списке со статусом «В очереди», транскрибация стартует автоматически без дополнительных действий.
- Пользователь открывает встречу, пока файл расшифровывается -> видит статус «В процессе» и процент выполнения, значения обновляются без перезагрузки страницы.
- Транскрибация завершилась -> статус «Готово», пользователь открывает текст транскрипта рядом с файлом.
- Транскрибация упала с ошибкой -> статус «Ошибка» с понятным сообщением и кнопка «Повторить».
- Пользователь загружает файл другого формата (не mp3/mp4) -> файл загружается как раньше, транскрибация не запускается, статус не отображается.
- Пользователь загружает несколько файлов подряд -> файлы транскрибируются по очереди, у каждого свой статус.
- Участник встречи (не владелец) открывает встречу -> видит статусы и тексты транскрипций файлов этой встречи.

## В скоупе

- Автоматический запуск транскрибации сразу после успешной загрузки файла форматов mp3 и mp4 (определение по расширению и MIME-типу).
- Локальный Whisper, модель `base`; язык распознавания — русский (фиксированный).
- Для mp4 расшифровывается звуковая дорожка.
- Статусы: «В очереди», «В процессе» (с процентом выполнения), «Готово», «Ошибка».
- Повторный запуск транскрибации для файла в статусе «Ошибка».
- Отображение статуса и прогресса в списке файлов встречи с автообновлением.
- Хранение результата и отображение текста транскрипта в интерфейсе встречи.
- Права доступа к транскрипту и статусу — те же, что к самому файлу встречи.
- Обработка состояния после перезапуска сервера: файлы, прерванные на середине, не остаются навсегда в статусе «В процессе».
- Конфигурация (путь к модели/бинарнику, параллелизм) через переменные окружения; описание в документации.

## Не в скоупе

- Другие модели Whisper (tiny, small, medium, large) и выбор модели пользователем.
- Выбор языка и автоопределение языка.
- Форматы кроме mp3 и mp4 (wav, m4a, webm и т. д.).
- Скачивание транскрипта файлом (txt, srt, vtt), таймкоды и субтитры в интерфейсе.
- Разделение по говорящим (диаризация).
- Редактирование текста транскрипта, поиск по транскриптам.
- Транскрибация уже загруженных до релиза файлов (миграция существующих данных).
- Отмена транскрибации в процессе.
- Использование внешних облачных сервисов распознавания.
- Уведомления (email, push) о завершении.

## Технические ограничения

- Whisper запускается локально на сервере; данные записей не покидают инфраструктуру.
- Максимальный размер файла — 500 МиБ (существующий лимит загрузки); транскрибация длинных записей может занимать значительное время, поэтому загрузка не должна блокироваться ожиданием расшифровки.
- Модель `base` даёт ограниченное качество на русском языке, особенно при шуме и нескольких говорящих; это принимаемое ограничение.
- Для mp4 нужно извлечение аудио, то есть на сервере должны быть доступны соответствующие системные инструменты (в том числе в Docker-образе `api`).
- Нагрузка на CPU высокая: одновременно выполняется ограниченное число задач, остальные ждут в очереди.
- Статус и результат должны переживать перезапуск `api` (хранятся в БД, файлы — в существующем томе `api_files`).
- Модель Whisper не хранится в репозитории; способ её получения и расположение описываются в документации.
- Существующие требования проекта сохраняются: JWT-авторизация, CQRS в модуле встреч, CORS только для `WEB_ORIGIN`.

## Критерии готовности

- [ ] После загрузки mp3-файла во встречу транскрибация запускается автоматически, в списке файлов виден статус «В очереди», затем «В процессе».
- [ ] После загрузки mp4-файла транскрибируется его звуковая дорожка, результат появляется так же, как для mp3.
- [ ] Загрузка файла завершается и возвращает ответ, не дожидаясь окончания транскрибации.
- [ ] Для файла в статусе «В процессе» отображается процент выполнения, значение растёт без перезагрузки страницы.
- [ ] По завершении статус меняется на «Готово», и в интерфейсе доступен текст транскрипта на русском языке.
- [ ] Используется только локальный Whisper с моделью `base`; обращений к внешним сервисам распознавания нет (проверяется по коду и сетевым вызовам).
- [ ] При ошибке (повреждённый файл, отсутствие аудиодорожки, сбой Whisper) статус «Ошибка» показывает причину, кнопка «Повторить» перезапускает транскрибацию и ведёт к «Готово» на исправном файле.
- [ ] Для файлов, не являющихся mp3/mp4, транскрибация не запускается и статус не показывается.
- [ ] При одновременной загрузке нескольких файлов задачи выполняются по очереди (не больше заданного лимита параллельных), у каждого файла свой корректный статус.
- [ ] После перезапуска `api` файлы, прерванные в статусе «В процессе», не зависают: они возвращаются в очередь или получают статус «Ошибка» с возможностью повтора.
- [ ] Статус и текст транскрипта доступны владельцу и участникам встречи и недоступны остальным пользователям (проверено тестом на 403/404).
- [ ] Удаление/недоступность файла не оставляет «висящих» задач, ломающих очередь.
- [ ] Работа запускается в Docker (`docker compose up -d --build api`): Whisper и инструмент извлечения аудио доступны в контейнере.
- [ ] Покрыто тестами: запуск после загрузки, смена статусов, ошибка и повтор, права доступа, отображение статусов в `web`.
- [ ] `CLAUDE.md` (корневой и `apps/api`, `apps/web`) и `README.md` обновлены: схема транскрибации, переменные окружения, получение модели.
- [ ] Проходят `npm run lint`, `npm run typecheck`, `npm run test`, `npm run format:check`.

# Plan: Загрузка файлов во встречу

**PRD:** [docs/prd-meeting-file-upload.md](./prd-meeting-file-upload.md)
**Дата:** 2026-10-13

## Открытый вопрос

В `apps/api/src/meetings` сейчас нет операции удаления встречи (есть только создание и чтение). Критерий PRD «при удалении встречи её файлы удаляются из хранилища и БД» в Фазе 3 закрыт на уровне данных и хранилища (каскад в БД + команда очистки файлов встречи), а эндпоинт удаления встречи в PRD не описан и в план не включён. Если он нужен в этой итерации, его нужно добавить в PRD.

## Фазы реализации

Тесты — часть каждой фазы, а не отдельный этап: фаза не считается готовой, пока тесты её функционала не написаны и не проходят (`npm run test`). В `api` — Vitest (unit рядом с кодом, e2e отдельно, нужна БД).

### Фаза 1: Участники встречи как id пользователей

**Цель:** Основа для проверки доступа: `Meeting.participants` содержит id существующих пользователей, а не произвольные строки.
**Затрагивает:** backend / database
**Задачи:**

- [ ] Валидация при создании встречи: каждый элемент `participants` — id существующего пользователя, иначе 400
- [ ] Миграция существующих данных `participants` к id пользователей
- [ ] Хелпер/запрос «является ли пользователь владельцем или участником встречи» (используется во всех следующих фазах)
- [ ] Unit-тесты: обработчик создания встречи (валидные id, несуществующий id, пустой список), хелпер доступа (владелец, участник, посторонний)
- [ ] e2e-тест: `POST` встречи с несуществующим участником → 400, с валидными → 201

**Когда готова:** Создание встречи с несуществующим id участника отклоняется; в БД нет `participants`, не являющихся id пользователей; тесты проходят.

### Фаза 2: Tracer Bullet — загрузка и список файлов (API)

**Цель:** Минимальный рабочий путь на бэкенде: участник загружает файл ≤ 500 МБ и видит его в списке встречи.
**Затрагивает:** backend / database
**Задачи:**

- [ ] Prisma-модель файла встречи (оригинальное имя, MIME-тип, размер, автор, дата, встреча, статус `Загружен`) + миграция
- [ ] Абстракция хранилища и реализация на локальном диске (каталог из переменной окружения, `.env.example`; имя на диске генерируется сервером) + unit-тесты: запись, чтение, удаление, имя с `../` не выходит за каталог
- [ ] Команда и эндпоинт загрузки (один файл, потоковая запись, лимит 500 МБ → 413, при обрыве или отмене частичные данные удаляются, записи в БД нет) + unit- и e2e-тесты: успешная загрузка, файл > 500 МБ, обрыв соединения
- [ ] Запрос и эндпоинт списка файлов встречи + unit- и e2e-тесты: список с метаданными, пустой список, файлы только своей встречи
- [ ] Проверка доступа на каждом запросе и CORS для `web` (3000 → 4000) с передачей JWT + e2e-тесты: 401 без токена, 403/404 для не владельца и не участника на загрузке и списке

**Когда готова:** Участник загружает файл и получает его в списке; файл > 500 МБ даёт 413 и не оставляет следов; посторонний получает отказ; все тесты фазы проходят.

### Фаза 3: Скачивание, сохранность и удаление файлов (API)

**Цель:** Завершить серверную часть: скачивание, переживание перезапуска, очистка при удалении встречи.
**Затрагивает:** backend / database
**Задачи:**

- [ ] Эндпоинт скачивания (принудительное вложение, оригинальное имя, потоковая отдача, проверка доступа) + unit- и e2e-тесты: заголовок `Content-Disposition: attachment`, имя, побайтовое совпадение с загруженным, 401 и 403/404, несуществующий файл → 404
- [ ] Каскадное удаление записей файлов вместе со встречей и команда очистки файлов встречи в хранилище + unit- и e2e-тесты: после удаления встречи нет записей в БД и файлов в хранилище, файлы других встреч не затронуты
- [ ] Каталог хранилища в docker — volume, не отдаётся как статика
- [ ] Автотест побайтового совпадения на файле > 100 МБ (e2e)
- [ ] Ручная проверка: файлы разных типов (видео, аудио, PDF, текст) и сохранность после перезапуска `api`

**Когда готова:** Скачанный файл побайтово совпадает с загруженным; файлы сохраняются после перезапуска; удаление встречи удаляет файлы из хранилища и БД; тесты api проходят.

### Фаза 4: Интерфейс — список файлов и скачивание (web)

**Цель:** На странице встречи виден раздел «Файлы» и можно скачать файл.
**Затрагивает:** frontend
**Задачи:**

- [ ] Тестовая инфраструктура в `apps/web` (сейчас в `web` нет тестового раннера): Vitest + Testing Library, скрипт `test`, чтобы `npm run test` и хук `pre-commit` запускали тесты `web`
- [ ] Раздел «Файлы» на странице встречи: список (имя, размер, дата, автор) и пустое состояние + компонентные тесты: рендер списка, форматирование размера и даты, пустое состояние
- [ ] Скачивание по клику (с JWT, под оригинальным именем) + тест: клик запрашивает нужный URL с токеном
- [ ] Обработка ошибок доступа и загрузки списка + тесты: сообщения для 401/403 и сетевой ошибки
- [ ] Адаптивность от 375 px и доступность с клавиатуры + тесты на роли/фокус (список, кнопка скачивания доступна с клавиатуры)

**Когда готова:** Участник видит файлы (или пустое состояние) на странице встречи и скачивает их; раздел удобен на 375 px и с клавиатуры; тесты `web` проходят.

### Фаза 5: Интерфейс — загрузка файла (web)

**Цель:** Участник загружает файл из интерфейса с прогрессом, отменой и повтором.
**Затрагивает:** frontend
**Задачи:**

- [ ] Кнопка выбора файла и drag-and-drop зона, один файл за раз + тесты: выбор через input, drop одного файла, несколько файлов не принимаются
- [ ] Проверка размера до отправки: файл > 500 МБ не отправляется, показано сообщение + тест: запрос не отправляется, сообщение видно
- [ ] Индикатор прогресса и кнопка отмены + тесты: прогресс обновляется, отмена прерывает запрос и файл не появляется в списке
- [ ] Сообщения об ошибках (в т. ч. 413) и повторная попытка + тесты: ошибка показана, повтор отправляет файл заново, в списке нет лишних записей
- [ ] Обновление списка после успешной загрузки; адаптивность от 375 px и доступность с клавиатуры + тесты: файл появляется в списке, зона загрузки доступна с клавиатуры

**Когда готова:** Из браузера загружается файл ≤ 500 МБ с прогрессом; отмена и ошибка не оставляют записей; повтор работает; тесты `web` проходят.

### Фаза 6: Документация и финальная проверка

**Цель:** Привести документацию в соответствие с кодом и подтвердить готовность.
**Затрагивает:** backend / frontend
**Задачи:**

- [ ] Обновить `CLAUDE.md`, `apps/api/CLAUDE.md`, `apps/web/CLAUDE.md`: хранилище, лимит, эндпоинты, правило `participants` = id пользователей, тестовый раннер в `web`
- [ ] Обновить `.env.example` и `README.md`: новые переменные окружения, volume
- [ ] Прогнать `npm run lint`, `npm run typecheck`, `npm run test`, `npm run format:check` и e2e-тесты `api` (с БД) — все тесты фаз 1–5 зелёные

**Когда готова:** Документация соответствует коду, все проверки и тесты проходят, критерии готовности PRD выполнены.

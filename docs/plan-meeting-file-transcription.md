# Plan: Транскрибация файлов встречи через локальный Whisper

**PRD:** docs/prd-meeting-file-transcription.md
**Дата:** 2026-10-15

## Фазы реализации

### Фаза 1: Tracer Bullet — транскрибация mp3 на backend

**Цель:** Загруженный mp3 автоматически расшифровывается локальным Whisper (`base`, ru) в фоне, статус и текст сохраняются в БД и отдаются в списке файлов. Загрузка не ждёт расшифровки.
**Затрагивает:** backend / database
**Задачи:**

- [ ] Prisma-модель транскрибации (статус: В очереди / В процессе / Готово / Ошибка, процент, текст, причина ошибки), связанная с файлом встречи; миграция
- [ ] Очередь задач с лимитом параллельных (переменная окружения) и сервис запуска локального Whisper (`base`, язык `ru`; путь к модели/бинарнику из переменных окружения, без внешних сервисов)
- [ ] Автопостановка в очередь после успешной загрузки файла mp3 (определение по расширению и MIME); для других форматов транскрибация не создаётся
- [ ] Возврат статуса и текста в списке файлов встречи в API (права те же, что у файла)
- [ ] Тесты: запуск после загрузки, ответ загрузки без ожидания, смена статусов, не-mp3/mp4 без транскрибации, очередь выполняет не больше лимита параллельных (Whisper замокан)

**Когда готова:** Загрузка mp3 через API возвращает ответ сразу; через `GET` списка файлов видно переход «В очереди» → «В процессе» → «Готово» с текстом; тесты проходят.

### Фаза 2: mp4, прогресс и причины ошибок

**Цель:** Транскрибируется звуковая дорожка mp4, в статусе «В процессе» отдаётся процент, при сбое сохраняется понятная причина.
**Затрагивает:** backend
**Задачи:**

- [ ] Извлечение аудиодорожки из mp4 перед запуском Whisper (с очисткой временных файлов)
- [ ] Расширение определения формата на mp4 (расширение и MIME)
- [ ] Разбор вывода Whisper и обновление процента выполнения в БД
- [ ] Классификация ошибок (повреждённый файл, нет аудиодорожки, сбой Whisper) в человекочитаемую причину
- [ ] Тесты: mp4-путь, рост процента, каждая категория ошибки даёт статус «Ошибка» с причиной

**Когда готова:** mp4 расшифровывается так же, как mp3; в списке файлов виден растущий процент; сбойные файлы получают «Ошибка» с причиной; тесты проходят.

### Фаза 3: Повтор, устойчивость и права доступа на backend

**Цель:** Ошибку можно перезапустить, очередь переживает рестарт и удаление файла, доступ ограничен участниками встречи.
**Затрагивает:** backend
**Задачи:**

- [ ] Эндпоинт повторного запуска транскрибации для файла в статусе «Ошибка» (через CQRS в модуле встреч)
- [ ] Восстановление при старте `api`: задачи в статусе «В процессе» возвращаются в очередь или получают «Ошибка»; «В очереди» подхватываются заново
- [ ] Обработка удалённого/недоступного файла без блокировки очереди
- [ ] Проверка прав: статус, текст и повтор доступны владельцу и участникам, остальным — 403/404
- [ ] Тесты: повтор (ошибка → готово), рестарт-восстановление, удалённый файл, права (403/404)

**Когда готова:** Повтор на сбойном файле приводит к «Готово»; после перезапуска нет зависших «В процессе»; посторонний пользователь получает 403/404; тесты проходят.

### Фаза 4: Frontend — статус и прогресс в списке файлов

**Цель:** Пользователь видит статус транскрибации и процент выполнения в списке файлов встречи с автообновлением.
**Затрагивает:** frontend
**Задачи:**

- [ ] Типы и Server Action получения статусов транскрибации для файлов встречи
- [ ] Отображение статуса и процента рядом с файлом (только для mp3/mp4; для остальных ничего)
- [ ] Автообновление (опрос) пока есть файлы в статусах «В очереди» / «В процессе», остановка после завершения
- [ ] Тесты (Vitest + Testing Library): отображение всех статусов, отсутствие статуса у других форматов, обновление без перезагрузки

**Когда готова:** После загрузки mp3/mp4 в UI виден статус, процент растёт без перезагрузки страницы; тесты проходят.

### Фаза 5: Frontend — текст транскрипта и повтор

**Цель:** Пользователь читает текст готового транскрипта и перезапускает транскрибацию после ошибки.
**Затрагивает:** frontend
**Задачи:**

- [ ] Просмотр текста транскрипта рядом с файлом при статусе «Готово»
- [ ] Показ причины ошибки и кнопка «Повторить» (Server Action повторного запуска)
- [ ] Тесты: показ текста, показ причины, клик «Повторить» вызывает действие и возвращает статус «В очереди»

**Когда готова:** Из UI можно прочитать транскрипт и повторить сбойную транскрибацию; тесты проходят.

### Фаза 6: Docker и документация

**Цель:** Фича работает в контейнере `api`, конфигурация и получение модели описаны.
**Затрагивает:** backend / инфраструктура
**Задачи:**

- [ ] Docker-образ `api`: Whisper и инструмент извлечения аудио доступны в контейнере; способ получения модели `base` (вне репозитория, например volume)
- [ ] Переменные окружения (путь к модели/бинарнику, параллелизм) в `.env.example`, `docker-compose.yml`, `apps/api/.env`
- [ ] Обновить корневой `CLAUDE.md`, `apps/api/CLAUDE.md`, `apps/web/CLAUDE.md` и `README.md`: схема транскрибации, переменные, получение модели
- [ ] Финальная проверка: `docker compose up -d --build api` + загрузка mp3/mp4 дают «Готово»; `npm run lint`, `typecheck`, `test`, `format:check`

**Когда готова:** Из чистого состояния `docker compose up -d --build api` расшифровывает загруженные mp3 и mp4; документация соответствует коду; все проверки проходят.

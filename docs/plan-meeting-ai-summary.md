# Plan: AI-выжимка встречи (summary, action items, решения)

**PRD:** docs/prd-meeting-ai-summary.md
**Дата:** 2026-10-15

## Ключевые решения

- Одна запись `MeetingSummary` на встречу (`meetingId` уникален, каскад со встречей): статус `IN_PROGRESS` / `DONE` / `ERROR`, `summary`, `actionItems` (JSON: `[{ description, assignee | null }]`), `decisions` (JSON: `string[]`), `error`. Статус «Не запускалась» — отсутствие записи; API отдаёт его как `NOT_STARTED` с пустыми списками.
- Запуск без очереди: команда атомарно переводит запись в `IN_PROGRESS` (повтор во время обработки — 409) и стартует фоновую задачу; ответ `202` не ждёт Claude.
- Вход — тексты транскрипций файлов встречи со статусом «Готово» и непустым текстом. Вызов — существующий `ClaudeService.ask` (`apps/api/src/claude`), модель из `SUMMARY_MODEL`. Ответ модели — строго валидируемый JSON.
- Права — `JwtAuthGuard` + `MeetingAccessGuard` (владелец и участники), как у файлов встречи; недоступная встреча — 404 по принятому в проекте правилу.
- Рестарт: зависшие `IN_PROGRESS` переводятся в `ERROR` (запуск ручной), отключается `SUMMARY_RECOVERY=off` (в e2e).

## Фазы реализации

### Фаза 1: Tracer Bullet — запуск и чтение выжимки на backend

**Цель:** По `POST` обработка стартует в фоне, Claude формирует summary, задачи и решения, результат сохраняется в БД и отдаётся по `GET`.
**Затрагивает:** backend / database
**Задачи:**

- [ ] Prisma-модель `MeetingSummary` и enum статусов, связь с `Meeting`; миграция
- [ ] `SummaryService` (модуль `src/summary`): сборка входа из готовых транскрипций, промпт (русский язык, только JSON, ответственный только если назван, транскрипт как данные), вызов `ClaudeService.ask`, парсинг и валидация ответа, запись `DONE`
- [ ] CQRS в модуле встреч: `GenerateMeetingSummaryCommand` (409, если нет готовых транскрипций; условный переход в `IN_PROGRESS` без параллельного запуска), `GetMeetingSummaryQuery` с view и состоянием `NOT_STARTED`
- [ ] Контроллер `POST /meetings/:meetingId/summary` (202) и `GET /meetings/:meetingId/summary` под `JwtAuthGuard` + `MeetingAccessGuard`
- [ ] Тесты (Claude замокан): юнит — валидный ответ → `DONE`, ответ в code fence, `assignee` отсутствует → `null`, запуск из состояний «нет записи» / `DONE`, отказ при `IN_PROGRESS` и без готовых транскрипций; e2e — запуск и чтение, ответ `GET` до запуска, два быстрых `POST` дают один 202 и один 409

**Когда готова:** `POST` на встрече с готовой транскрипцией возвращает 202, а `GET` показывает переход `IN_PROGRESS` → `DONE` с summary, задачами (с ответственным или без) и решениями; тесты проходят.

### Фаза 2: Ошибки, права доступа и устойчивость

**Цель:** Сбои обработки превращаются в понятную ошибку с возможностью повтора, доступ ограничен участниками, прерванная обработка не зависает.
**Затрагивает:** backend
**Задачи:**

- [ ] Классификация ошибок: `SummaryError` с готовым русским сообщением (Claude не настроен или недоступен, невалидный ответ, слишком длинный транскрипт), остальное — общее сообщение, детали только в логе, токен не попадает в логи
- [ ] Лимит размера входа `SUMMARY_MAX_INPUT_CHARS`: превышение — `ERROR` без вызова Claude и без обрезки текста
- [ ] Повторный запуск из `ERROR` и пересоздание из `DONE`: новый результат заменяет прежний
- [ ] Восстановление при старте: зависшие `IN_PROGRESS` → `ERROR` с сообщением, отключается `SUMMARY_RECOVERY=off`
- [ ] Тесты: каждая категория ошибки даёт `ERROR` с сообщением, лимит без вызова Claude, повтор после ошибки и замена результата, recover, права (участник не владелец запускает и читает, посторонний — 404, запуск прямым вызовом API недоступен)

**Когда готова:** сбойная обработка завершается `ERROR` с понятной причиной и успешно повторяется, после рестарта нет вечных `IN_PROGRESS`, посторонний не получает ни статус, ни результат, ни запуск; тесты проходят.

### Фаза 3: Frontend — запуск и просмотр результата

**Цель:** Пользователь запускает обработку кнопкой на странице встречи и видит статус и готовую выжимку без перезагрузки страницы.
**Затрагивает:** frontend
**Задачи:**

- [ ] Типы и функции получения выжимки (`src/lib/summary.ts`), Server Actions `generateSummary` и `refreshMeetingSummary`
- [ ] Карточка «Выжимка» на странице встречи: кнопка «Сформировать выжимку» (недоступна с пояснением, если нет файлов с готовой транскрипцией; блокируется во время обработки), статус «В процессе»
- [ ] Автообновление статуса (опрос) до перехода в «Готово» или «Ошибка»; состояние переживает перезагрузку страницы
- [ ] Отображение блоков «Резюме», «Задачи» (с ответственным, если указан) и «Решения»; пустое состояние блока («Решений не найдено»)
- [ ] Тесты (Vitest + Testing Library) и визуальная проверка по `apps/web/CLAUDE.md` (Playwright MCP, скилл `ui-ux-pro-max`, мобильная ширина, тёмная тема)

**Когда готова:** из UI можно запустить обработку и увидеть резюме, задачи и решения после завершения; кнопка недоступна без готовых транскрипций; тесты и визуальная проверка пройдены.

### Фаза 4: Frontend — ошибки, повтор и пересоздание

**Цель:** Пользователь видит причину сбоя, повторяет обработку и пересоздаёт готовую выжимку.
**Затрагивает:** frontend
**Задачи:**

- [ ] Отображение статуса «Ошибка» с сообщением и кнопка «Повторить»
- [ ] Кнопка пересоздания при готовой выжимке; новый результат заменяет прежний после завершения
- [ ] Сообщения об ошибках Server Actions (409 «уже запущена» / «нет готовых транскрипций», 404, недоступность сервера)
- [ ] Тесты: показ ошибки и «Повторить», пересоздание заменяет результат, обработка 409/404/сети; визуальная проверка состояний ошибки (мобильная ширина, тёмная тема)

**Когда готова:** из UI можно повторить сбойную обработку и пересоздать готовую выжимку; ошибки показаны понятно; тесты пройдены.

### Фаза 5: Конфигурация, Docker и документация

**Цель:** Фича работает в контейнере `api`, конфигурация и вопросы приватности описаны.
**Затрагивает:** backend / инфраструктура
**Задачи:**

- [ ] Переменные `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `SUMMARY_MODEL`, `SUMMARY_MAX_INPUT_CHARS`, `SUMMARY_RECOVERY` в `.env.example` и сервисе `api` в `docker-compose.yml`
- [ ] Проверка, что Claude Agent SDK запускается внутри образа `api`
- [ ] Обновить `CLAUDE.md` (корневой, `apps/api`, `apps/web`) и `README.md`: модуль `src/summary`, эндпоинты, переменные, отправка транскрипта во внешний сервис
- [ ] Финальная проверка: `docker compose up -d --build api` формирует выжимку; `npm run lint`, `typecheck`, `test`, `format:check`, e2e `api` проходят

**Когда готова:** из чистого состояния контейнер `api` формирует выжимку, документация соответствует коду, все проверки проходят.
